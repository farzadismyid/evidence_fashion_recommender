# Systematic robustness protocol

The original modular result bundle is frozen before this phase and compared with the
new held-out results. Human evaluation is deliberately excluded and remains future work.

## Leakage control

Outfits—not individual items—are deterministically hashed into 60% development, 20%
validation, and 20% test partitions. Each reported partition contains 60 cases for each
of the five target categories. The CLI rejects prompt or reranking selection inputs from
the wrong partition.

The validation partition selects:

- evidence-reranking weight by NDCG@10, then HitRate@10 and reciprocal rank;
- Hybrid-RAG word budget, evidence count, and prompt order using a declared automatic
  grounding score plus independent-judge quality.

The test partition is opened only after these choices are recorded. Test outcomes never
change a selected configuration.

## Robustness matrix

The four explanation variants are generated by pinned Llama 3.2, Mistral, and Gemma 3
12B models. Every explanation is independently evaluated by pinned Qwen3 8B, Mistral,
and Gemma 3 12B judges. Reported robustness measures include:

- each judge dimension and the explicitly defined unweighted overall mean;
- paired bootstrap intervals with Holm and Benjamini-Hochberg corrections;
- pairwise judge Spearman agreement and mean absolute disagreement;
- claim-level supported, unsupported, and not-verifiable labels;
- claim-label format compliance, with deterministic normalization of recognizable variants
  and conservative `not_verifiable` handling for descriptive/non-categorical responses;
- deterministic faithfulness, citation, leakage, and corrected substitution metrics;
- KB-proxy and multi-judge-consensus rule-retrieval quality.

Multiple model judges and deterministic checks remain systematic proxy evidence. They
must not be described as human preferences, human relevance judgments, or user studies.
